# Лог рішень

Формат запису: **проблема → варіанти → рішення → чому**.
Потрібно щонайменше 5 записів до кінця проєкту. Новий запис додає той, хто прийняв рішення.

## D-001. Мова реалізації
- **Проблема:** обрати мову програмування для всього проєкту.
- **Варіанти:** (1) Python; (2) C# (.NET).
- **Рішення:** C# (.NET 10). `replication.py` лишається на Python і запускається як зовнішній процес через `Integration/Replication/ReplicationBridge.cs`.
- **Чому:** команда краще знає C#; у .NET є готові PBKDF2, AES і HMAC; `dotnet test` дає одну команду для тестів.
- **Ризик:** підтвердити з викладачем, що реалізація не на Python прийнятна й як запускається перевірка.

## D-002. Структура рішення
- **Проблема:** як розділити код між п'ятьма людьми, щоб не заважати одне одному.
- **Варіанти:** (1) один спільний проєкт; (2) один проєкт (модуль) на людину.
- **Рішення:** окремі проєкти `Compression`, `Scheduler`, `Classifier`, `Security`, `Integration` плюс спільний `Core` (типи, що потрібні кільком модулям: `LogRecord`).
- **Чому:** менше конфліктів при merge, зрозуміло, хто за що відповідає; `Core` не дає виникнути циклічним залежностям між проєктами.

## D-003. Формат 16-байтового запису
- **Проблема:** оригінальний `FORMAT_SPEC_P3.md` ще не отримано, а `RecordCodec` потрібен іншим модулям.
- **Варіанти:** (1) чекати на специфікацію; (2) зафіксувати власну робочу версію й звірити пізніше.
- **Рішення:** робоча версія в `docs/FORMAT_SPEC_P3.md`: little-endian, `int64` час, `uint16` джерело й код, `int16` метрика, упаковані Category/Severity/Critical в одному байті, байт прапорців.
- **Чому:** розблоковує роботу команди; вся розкладка зосереджена в `RecordCodec`, тож заміна формату торкнеться одного файлу.
- **Ризик:** формат може не збігтися з `session.bin` — звірити, щойно специфікація з'явиться.
